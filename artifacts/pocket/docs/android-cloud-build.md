# Build Pocket for Google Play without Android Studio

Pocket's manually triggered GitHub Actions workflow generates a signed Android App Bundle (`.aab`). It uses Expo prebuild and Gradle directly, not EAS CLI or Replit's iOS publishing flow.

**This workflow does not publish or submit anything to Google Play.**

## One-time setup

Repository: https://github.com/mohsinriaz18/pocket

Go to **Settings → Secrets and variables → Actions → New repository secret**.

### Public mobile configuration

The build needs these three public mobile values, stored as Actions secrets to avoid logging them:

- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY` — only a publishable/anon key, never a service-role key.
- `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` — the public `goog_` SDK key from Pocket's RevenueCat Android app, never a RevenueCat secret key.

These are embedded in the mobile application by Expo. Supabase Row Level Security remains responsible for protecting financial data. Never add `GH_TOKEN`, `SUPABASE_ACCESS_TOKEN`, Google service-account JSON or server credentials to this build.

### Android upload signing

The build needs:

- `ANDROID_KEYSTORE_BASE64` — Base64 encoding of your upload keystore file.
- `ANDROID_KEYSTORE_PASSWORD` — that keystore's password.
- `ANDROID_KEY_ALIAS` — the upload key alias inside the keystore.
- `ANDROID_KEY_PASSWORD` — the upload key's password.

If Pocket has ever been uploaded to Play, reuse its existing upload key. If it is lost, use Google Play's upload-key reset process. Do not silently create a replacement key.

For a first Android upload, generate a new upload key and keep a secure backup of the keystore, alias and passwords before the first upload. Use Play App Signing when prompted; Google manages the app-signing key, while this workflow uses your upload key.

Do not paste signing credentials into chat, commit them to Git, or upload them as public GitHub build artifacts. The workflow uploads **only** the signed `.aab`. The temporary keystore is created with private filesystem permissions and removed after each run.

## Run a build

1. Open https://github.com/mohsinriaz18/pocket/actions/workflows/pocket-android.yml.
2. Select **Run workflow** and choose branch **main**.
3. Enter an Android **version code**. Use `1` for the first Play upload, otherwise a number higher than every version already uploaded. Rebuilding the same source does not allow reusing a version code for a new Play upload.
4. Start the workflow and wait for a successful run. Native Android builds can take several minutes.
5. Open the completed run and download the `pocket-android-…` artifact.
6. Unzip it. The upload file is `app-release.aab`.

The package is always `com.pocketwealth.app`. The version code is set only in the runner's copy of static `app.json`. Billing permission is added before generating the native project. The source app version name comes from `app.json`.

The workflow is manual-only: pushing code from Replit does not start builds or submit releases.

## Upload for subscription setup

In Google Play Console, open **Pocket → Test and release → Testing → Internal testing → Create new release**.

Upload `app-release.aab`, complete the release details, and roll out to internal testing only. Follow any Play App Signing prompts. Once Play recognizes the billing-enabled build, return to **Monetize with Play → Products → Subscriptions**.

Use [android-subscriptions.md](android-subscriptions.md) to activate the monthly/yearly plans and seven-day offers.

## Troubleshooting

- **Missing signing configuration:** Add all four signing secrets; no unsigned/debug-signed bundle is produced as a fallback.
- **Wrong keystore/password/alias:** Correct the Actions secrets. Do not generate a different key for an existing Play app.
- **Wrong signing certificate in Play Console:** Confirm the keystore matches the registered upload certificate or request an upload-key reset.
- **Version code already used:** Run another build with a higher code.
- **Android SDK/toolchain failure after an Expo/React Native upgrade:** Align this workflow's SDK, NDK, Java and Gradle settings with the native project generated by that version.
- **Subscriptions still show “Upload a new APK”:** Confirm the internal-test release was processed and contains Google Play billing. Check merchant/payments setup if the billing-enabled release is already available.

Local helper checks:

```sh
node --test artifacts/pocket/tests/android-release.test.mjs
```

Helper tests and successful Expo JavaScript exports are not proof of a signed native build. A signed `.aab` exists only after the GitHub workflow finishes successfully.
